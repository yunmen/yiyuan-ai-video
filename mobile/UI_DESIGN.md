# 千溪 mobile 用户端 UI 设计

## 设计方向

本轮使用 `high-end-visual-design` 技能的 Editorial Luxury 方向，结合现有千溪水墨品牌，形成「纸白影像工作室」：暖纸白背景、深墨标题、朱砂主行动、同心圆角卡片、轻线图标与悬浮导航。

移动端以易上手为首要目标，保留现有 uni-app Vue3、接口、鉴权、素材上传、生成、支付和轮询链路。页面通过真实数据渲染，不加入演示账号、虚构额度、伪造作品或生成结果。首页水墨图沿用本地品牌资源，并明确注明「品牌视觉示意」。

## 页面与用户路径

| 我的作品 | 真实余额、四类状态筛选、作品瀑布流 | 查看进度、播放、详情、重试 |
| 个人中心 | 账号身份、额度卡片、常用服务 | 登录、管理形象、充值、退出 |
| 账号设置 | 头像、昵称、用户名与密码分组，统一校验与提交状态 | 修改资料或密码 |
| 我的素材 | 图片/视频筛选、上传历史卡片、预览与分页 | 找回历史素材、查看已上传文件 |
| 邀请好友 | 邀请码主卡片、双方奖励说明与邀请统计 | 复制邀请码或邀请链接 |
| 消耗记录 | 额度流水、扣款与退款筛选、关联任务 | 查看变动与任务详情 |

| 分镜编辑 | 延续统一令牌、成片区域、分镜与质量状态 | 修改提示词、保存或局部重跑 |

## 设计令牌

令牌定义在 `src/uni.scss`，相同值在 `src/App.vue` 的 `page, :root` 作用域公开给 H5 与小程序使用。修改令牌时应同步这两处。

| 类型 | 值与用途 |
| --- | --- |
| 页面底色 | `#F8F7F3` |
| 卡片内芯 / 托盘 | `#FFFEFA` / `#EFEDE7` |
| 主文字 / 次级文字 | `#25241F` / `#48463F` |
| 辅助文字 | `#77746B`；`#969187` 仅用于弱化信息 |
| 品牌主色 | `#B23A2E` |
| 状态色 | 成功 `#4B7A5A`、提示 `#3E6B7A`、警告 `#B98236`、失败 `#B23A2E` |
| 字体 | 正文优先苹方、微软雅黑；标题优先宋体；不依赖远程字体 |
| 字号 | 首页主标题 42px，工具标题 25px，区块标题 23px，正文 13–14px，辅助信息 10–12px |
| 圆角 | 10 / 14 / 20 / 28px；主行动胶囊形；主要卡片外壳 24px、内芯约 18px |
| 间距 | 4px 基准，页面边距 20px，区块间距 24–34px |
| 页面宽度 | 最大 480px，宽屏居中 |
| 导航 | 底部悬浮四项导航，距离安全区 12px，页面预留 84px 基础避让 |
| 动效 | `cubic-bezier(0.22, 1, 0.36, 1)`；主要使用透明度与位移；H5 尊重减少动态效果 |

## 组件与交互

- 主操作保持一项，使用朱砂胶囊按钮；带箭头的主行动使用独立圆形图标内芯。
- 卡片用纸色托盘与浅色内芯建立层次，保持同心圆角，不依赖沉重阴影。
- 共享 `AppTabBar` 使用 uni-app 按钮并显式补齐 H5 键盘操作，支持键盘焦点和 `aria-current`，重复点击当前项不重新导航。
- `AppNavBar` 返回按钮使用 uni-app 按钮，补齐键盘操作并保留 44px 触控区，并继续避让微信胶囊。
- `AppEmpty` 提供明确标题、说明与恢复操作，不能用虚构数据填补空态。
- `AppField` / `AppTextarea` 继续使用 uni 原生表单，统一值同步、输入事件与中文可访问名称；H5 输入节点最低 16px，避免 iOS 聚焦时自动放大。
- 小程序开启 `mergeVirtualHostAttributes`，表单组件使用单个原生根节点和虚拟宿主，让页面传入的尺寸、间距和圆角落在真实控件上。H5 名称同步代码经条件编译从小程序产物移除。
- `ToolCost` 统一展示费用、余额、计算中与失败重算入口；页面额外说明预计耗时，避免重复显示费用。
- H5 的费用确认、作品搜索、原生菜单和选择器应用纸白样式；小程序继续使用原生交互，由 `utils/feedback.js` 统一朱砂确认色和深墨文字色。
- 数字人设置提供固定的 44px 关闭入口，表单在独立区域滚动并预留安全区；生成进度、视频播放与素材预览遵循公共弹层层级。
- 二级页通过分享链接直达时也显示返回入口，无上一页则返回首页。
- `AppIcon` 继续用现有 SVG Data URI 路径兼容 H5 与小程序，默认描边 1.5px。
- 工具说明区放入公共样式，页面不重复定义同一套排版。
- 工作台底部生成栏与悬浮导航分别避让安全区，页面末尾留出对应高度。
- 生成中、完成、失败使用「颜色 + 中文文字」共同表达，进度继续来自后端。

## Figma 交付

本会话没有可调用的 Figma 连接工具，因此本轮提供本地可导入 Figma 的交付包，没有创建或同步在线 Figma 文件。

交付目录：仓库根目录 `_design/mobile-ui/`。该目录按仓库规则忽略 Git，设计文件保留在本地，不包含在代码差异中。

- `index.html`：12 页浏览画廊，支持按页面筛选，链接各 SVG 与截图。
- `千溪-mobile-设计总览.svg`：12 页整板，可拖入 Figma。
- `screens/*.svg`：每页 390 × 844 的独立 SVG。文字、形状与线性图标保留可编辑图层，品牌图片为内嵌位图。
- `screens/*.png`：来自实际 mobile 页面的对应截图，用于检查导入效果。
- `design-tokens.json`：设计令牌备份。
- `Figma导入说明.md`：操作与限制说明。

导入 SVG 不会自动创建 Figma Auto Layout、组件变体或可点击原型。可点击的真实界面通过 `npm run dev:h5` 预览。

设计包的作品、账号、余额、数字人和套餐填充数据仅在本地截图浏览器中生成，不进入产品代码；这些数字不代表正式价格或可用额度。数字人无图时使用现有图标占位，避免使用未授权人物素材。

## 验证边界

构建与交互检查结果以任务交付说明为准。当前设计验收不连接服务器，不执行真实上传、短信、视频生成、支付或充值。微信小程序需要后续在开发者工具与真机中验证原生组件、安全区和胶囊布局。


## mobile 完整应用结果

实际源码覆盖 `pages.json` 注册的全部 16 页，沿用当前纸白背景、朱砂主行动、双层卡片和悬浮导航。补齐了工具设置、生成结果、费用状态、充值记录与原生弹窗的视觉；首页模板、作品、数字人和套餐读取失败时均提供同页重试入口。

本轮实际页面截图和浏览画廊位于 `_design/mobile-applied/`，包含 16 页长图及数字人设置、费用确认、生成结果、充值记录和工作室进度等展开状态。`验收结果.json` 保存宽度、运行时异常和交互检查结果。此前的 12 页 SVG 设计包仍保留在 `_design/mobile-ui/`。

本轮验证已通过：

- `npm run build:h5` 与 `npm run build:mp-weixin`。
- 16 页 × 320 / 375 / 390 / 768px 的 64 项布局检查，以及 7 项展开状态检查，共 71 项；无横向溢出、固定操作与导航重叠或页面运行时异常。
- 13 项交互与状态检查，包括形象设置、费用重算、网络恢复、生成结果、工作室进度、二级页返回和登录注册表单。
- 个人中心及四项服务在 375 / 390 / 768px 下的回归，以及头像、资料、素材、退款筛选和登录回跳等界面流程。
- 小程序产物的表单值绑定、输入事件、虚拟宿主样式透传，以及 H5 节点访问代码的条件编译检查。
- `git diff --check`。

页面交互验证使用本地接口展示样例，未执行真实后端、短信、AI 生成、支付与充值联调；未进行微信开发者工具和真机实测；未连接在线 Figma 账号。

## 界面遗漏复查（2026-10-20）

对全部 16 个注册路由及 9 个公共组件再次核对，重点补查主页面之外的复刻解析结果、素材绑定、文案确认、分镜展开、原生选择器、作品菜单与个人服务状态。

本次发现并修复：

- 工作室「粘贴视频链接」的原生输入区域高度为 0：补足 48px 控件高度，并改用当前纸色令牌。
- 文案确认的大标题、副标题缺少表单样式：接入现有 `app-field`，补齐标签间距；修正全局原生输入节点的字号选择器，保证实际输入文字至少 16px。
- 素材说明、状态和关联操作挤在同一行：说明与操作分行，分类标题在窄屏下换行；复用素材、上传、主参考图与删除操作采用明确的独立区域。
- 已上传参考图的主图按钮超出图片卡片：将图片预览、主图按钮与删除热区分别放入卡片，320px 下参考图降为两列；补齐预览名称与键盘操作。
- 复刻摘要仍保留旧的侧边条样式：统一为纸色双层卡片；补齐创意档位换行、分镜时间换行和长主按钮的高度适配。
- H5 音色选择器样式未命中实际的 `uni-picker-custom`；按需载入的原生样式还会覆盖确认色与宽屏菜单：修正选择器精度、盒模型、颜色、滚轮遮罩、圆角、安全区与宽度，宽屏保留菜单取消入口。
- 换口播功能名称在窄屏被挤成竖排：图标与名称上下排列，保留完整名称；作品播放补齐键盘关闭入口，工作室折叠设置补齐展开状态与入场反馈。
