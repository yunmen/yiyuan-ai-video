# 移动端素材签名直传方案

## 1. 背景与范围

原上传链路为：手机 → 后端接收完整文件 → 后端转存 COS → 返回素材地址。慢上行和后端转存等待都会消耗客户端超时时间。

本次将 `mobile` 的 H5 素材上传改为优先签名直传，复用 `desktop` 已使用的后端协议，不修改已冻结的 `desktop`。直传绕过业务服务器中转，通常能减少大文件上传耗时，但实际效果依赖用户网络和桶地域，未承诺固定提速比例。

| 平台 | 本次策略 |
| --- | --- |
| H5（包括手机浏览器） | 优先申请签名并 PUT 原始文件；签名不可用时回退中转 |
| 微信小程序 | 继续使用 `uni.uploadFile` 中转，不包含浏览器上传代码 |
| App | 继续使用 `uni.uploadFile` 中转；本次未验证 App 构建或真机 |

小程序/App 的签名直传需另行适配文件二进制读取、PUT、进度和域名限制，不可直接把 multipart 上传地址替换成 PUT 签名地址。

## 2. 调用链与协议

1. 页面调用 `uploadMedia(filePath, options)`。
2. H5 优先使用 `options.file` 原始 Blob/File；旧图片入口只传临时地址时，读取该地址取得 Blob，并根据 MIME 推导签名文件名。
3. 本地拒绝空文件及超过 `50 * 1024 * 1024` 字节的文件。
4. 通过现有集中 API 与统一请求层调用 `POST /api/user/v1/base/common/upload/sign`，请求 JSON 为 `{ "filename": "video.mp4" }`；鉴权仍由统一请求层附加 Bearer Token。
5. 成功响应包含 `data.uploadUrl`、`data.url`、`data.filename`。浏览器通过独立 XHR 向 `uploadUrl` 执行 PUT，请求体为原始文件，不是 FormData。
6. COS 返回 HTTP 2xx 后，上传函数返回 `{ url, filename, size }`，其中 `size` 为文件字节数。

COS PUT 不附加业务 Authorization、Cookie 或全局业务请求头，仅按文件类型设置 Content-Type。签名 URL 自带临时授权，不得在日志、截图或文档中记录实际签名参数。

上传进度维持页面原有的 0–100 口径；H5 发送进度最高显示 99%，收到 COS 成功响应后才回调 100%。上传超时统一使用 `config.UPLOAD_TIMEOUT`，当前为 600000 毫秒，普通接口超时仍为 10000 毫秒。后端当前签名有效期为 600 秒，签发后立即开始上传，不缓存或复用签名。

## 3. 回退与错误边界

- 签名接口业务失败（例如对象存储未启用）、网络异常或返回不可用签名时，回退 `/api/user/v1/base/common/upload/file` multipart 上传。
- 无法确定签名文件名时，使用原中转路径。
- 明确鉴权失效及 HTTP 401、403、429 不回退，避免绕过登录、权限或限流处理。
- 取得有效签名并开始 PUT 后，超时、跨域或 COS HTTP 错误直接报错，**不自动二次中转**，防止同一大文件重复传输。
- 素材读取失败、空文件和超限在申请签名前直接拒绝。
- 中转接口继续使用表单字段 `file`，H5 同时透传原始文件对象；其他端保持现有临时路径上传方式。

## 4. 素材归属与服务端校验

复用现有后端逻辑，不新增匿名上传能力、不新增完成回调接口：

- 签名接口需要用户登录，并检查文件扩展名和上传频控。
- 签名签发时登记当前用户的素材归属，状态为 `pending`。
- 在调用现有 `verify_materials` 的后续业务中，服务端 HEAD 对象，检查对象存在且大小在有效范围后标记为 `ready`。
- 不可仅因公开 URL 可访问，就把其他账号的素材认领为当前用户素材。

前端大小检查是体验优化，不替代服务端校验；后续新增素材消费入口时，必须检查是否接入归属和对象大小校验。

## 5. 代码位置

- `mobile/src/utils/upload.js`：文件读取、签名获取、H5 PUT、进度及中转回退。
- `mobile/src/utils/media.js`：视频选择结果保留 H5 原始 File。
- `mobile/src/pages/studio/index.vue`：对标视频传入原始文件与文件名。
- `mobile/src/pages/render/index.vue`：换口播视频传入原始文件与文件名。
- `mobile/src/config/index.js`：上传独立超时配置。
- `mobile/src/api/model/common.js`：复用已有 `uploadSign` API。
- `backend/app/routes/user/common.py`：复用已有签名接口。
- `backend/app/core/oss.py`：复用现有 PUT 签名与标准区域 HTTPS 域名。
- `backend/app/services/user_material.py`：复用已有素材归属和对象校验。

本次未新增依赖、未修改后端接口及数据库结构。

## 6. COS 与上线要求

部署前由有权限的运维确认：

1. 后端对象存储配置已启用，服务端凭据具备签名及后续对象 HEAD 所需权限；凭据只保存在服务端。
2. COS CORS 允许实际 H5 来源。来源须匹配完整的协议、域名/IP 和端口，例如当前 IP HTTP 站点与未来 HTTPS 域名须分别配置；优先使用明确来源，避免无必要的通配开放。
3. 允许 PUT 方法、Content-Type 请求头及浏览器预检；由 COS 正确响应 OPTIONS。
4. 当前代码不读取 ETag 等响应头，无需为本方案额外暴露 ETag。
5. 手机网络可以访问签名返回的标准区域 HTTPS 域名，素材公开 URL 也可供现有下游业务读取。
6. 发布更新后的 mobile H5 静态产物，并确认入口页及资源缓存已更新。不要仅构建而未发布，就认为线上链路已切换。

CORS 只允许浏览器跨域访问，不替代签名鉴权，也不应为此把存储桶改成公共可写。

## 7. 验收与验证记录

本地已执行成功：

- 在 `mobile` 执行 `npm run build:h5`。
- 在 `mobile` 执行 `npm run build:mp-weixin`，验证非 H5 条件编译。
- 执行 `git diff --check -- mobile/src`。
- 用 Node 内存模拟验证：签名成功直传、99→100 进度、不附加业务 Token、签名不可用回退、PUT 失败不回退、鉴权失效阻断、空文件与超限拒绝、临时地址读取。
- 修改源码的 IDE 诊断未发现问题。

上述模拟不等同于真实 COS 联调。本次未部署、未更改线上 COS CORS、未进行手机真机上传和 App 验证。

上线后验收：

- 使用真实图片、小视频和接近但不超过 50MiB 的视频测试。
- 浏览器网络面板应显示先请求 `/upload/sign`，然后直接 PUT COS，正常场景不出现 `/upload/file`。
- 检查 PUT 没有携带业务 Bearer Token；不要对外分享含签名 URL 的网络记录。
- 确认进度在 COS 成功响应后才达到 100%，返回 URL 可用于后续解析/生成及素材归属校验。
- 在对象存储未启用的测试环境验证签名不可用时中转仍可用。
- 在测试环境制造跨域/网络失败，确认直接报错、不重复中转。
- 小程序真机验证继续走中转路径；构建通过不能替代合法域名和真机网络检查。

若进度已发送完但 COS 拒绝请求，优先检查签名有效期、CORS、桶权限和网络；若正常请求仍出现 `/upload/file`，检查签名接口响应和 H5 静态资源是否已经更新。
