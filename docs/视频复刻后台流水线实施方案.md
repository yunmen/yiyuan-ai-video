# 视频复刻后台流水线实施方案

## 1. 目标与边界

保持当前项目主体核心不变：继续使用 mobile、FastAPI backend、Redis / ARQ worker、现有任务表、额度机制、存储和供应商网关。不修改冻结的 desktop，不迁移框架，不新增独立微服务。

用户默认只需上传参考视频、产品图并发起生成；补充要求为选填。探测、分析、规划、提示词编译、能力路由、生成、拼接、检查与归档由后台完成。不得新增必须理解分镜、模型、供应商、提示词或重试参数的操作。已有可选分镜编辑保留，但不作为生成前置步骤。

“主体核心不变”指项目架构与主要业务不变；画面中的人物、产品、场景是否替换仍遵循已有素材绑定与替换意图，不改变历史语义。

## 2. 当前实现与差距

当前链路为 mobile → backend 建单及额度校验 → ARQ → worker 提示词组装 → 视频编辑或分段生成 → 质检及后处理 → 回调保存媒体 URL。

已有能力：媒体探测与适配、元素检测与绑定、独立分镜拆解、短视频整片编辑、长视频分段与尾帧续接、检查点恢复、局部重跑、任务与镜头持久化。

主要差距：拆解与生成之间没有统一的结构化镜头快照；移动端编辑主要通过 remark 传递；产品领域迁移不是独立规划层；路由是配置驱动，尚非成本质量联合决策；产物以 URL 和数据库为主，没有统一导出清单。

供应商事实：已有方舟原生与 OpenAI 兼容视频协议，不代表已完成可灵、万相、VEO 官方适配。

## 3. 目标逻辑链路

参考视频 + 产品图 + 选填要求
→ 素材规范化
→ 人物处理策略
→ 参考结构分析
→ 产品迁移规划
→ 提示词编译
→ 能力与预算路由
→ 生成执行
→ 质检、拼接、归档。

逻辑阶段不等于独立进程，也不意味着强制逐段生成。短视频保留整片编辑优先，长视频继续分段，避免额外成本与接缝。

### 3.1 模块职责

| 模块 | 输出 | 职责与复用点 |
| --- | --- | --- |
| 素材接入 | MediaManifest | 复用 media_prep，保存原片、探测结果和派生素材，避免重复下载探测 |
| 人物策略 | IdentityPolicyResult | 记录保留、替换或授权风格化策略；复用既有检测与处理 |
| 参考分析 | ReferenceDNA | 镜头时间、景别、运镜、节奏、转场、旁白、置信度 |
| 产品迁移 | AdaptedPlan | 真实产品事实、替换关系、保留项、动作适配、禁止改变项 |
| 提示词编译 | SegmentSpec[] | 按镜头与段生成目标提示词，绑定素材、连续性约束与版本 |
| 模型路由 | RouteDecision | 先过滤能力、时长、画幅和健康度，再比较费用、质量与耗时 |
| 供应商适配 | ProviderTask | 统一提交、查询、取消、错误分类和结果归一化，显式声明能力 |
| 执行与恢复 | RunManifest | 复用 ARQ、外部任务 ID、检查点、尾帧衔接、拼接与重试预算 |
| 产物归档 | ArtifactManifest | 记录段产物、成片、提示词版本、费用与质检结果 |

人脸或人体检测并不自动意味着必须彩铅化；彩铅只是可选风格，不能替代授权或保证合规。不得以处理素材规避供应商审核。产品功效、参数和规格必须来自已确认事实，不由模型编造。

## 4. 分期推进

### 第一期：贯通可信分镜快照

不增加用户操作、不新增数据库列、不增加模型调用。

- CreateSchema 增加可选 deconstruct_id，沿用现有分镜任务命名；已有分析自动携带，没有则沿用当前后台生成路径。
- 可选 shot_overrides 只允许修改已验证镜头的描述、旁白，不接受客户端修改时间轴或伪造镜头。
- backend 在扣费前校验本人、同原片、未删除、成功拆解及有效时间轴，固化 version=1 的 shot_plan。
- 优先采用已保存的 usage.shot_prompts，再合并本次可选编辑；建单快照不受来源后续修改影响。
- worker 透传 shot_plan，短视频将镜头约束加入整片编辑；长视频复用时间轴和描述，缺描述才补充逆推。
- 多段执行优先级：已有 checkpoint > 建单快照 > 现有自动分析。
- 第一期采取保守策略：有替换意图时仅复用时间轴，不直接注入来源描述与旁白；长片沿用现有意图感知逆推，避免原主体覆盖新素材。因此替换任务的镜头文字修改虽已固化，但本期不承诺用于生成；待第二期完成结构与主体分离、产品迁移后启用。
- 保持九宫格 shot_prompts 字符串列表协议、计费和自动重跑默认值不变。

第一期不声称已完成完整 ReferenceDNA、跨领域迁移或智能选模。没有显式拆解的任务继续现有自动处理；统一后台分析阶段留待第二期，不为本期额外强制分析短片。

### 第二期：后台统一分析与产品迁移

在生成任务内自动准备 ReferenceDNA 与 AdaptedPlan，不要求用户点击拆解。按素材摘要、分析版本与访问权限复用分析，明示分析失败、置信度不足的状态。完善结构化转场与目标产品动作适配。分析必须纳入成本及超时预算，不能静默增加无限模型调用。

### 第三期：产物清单与可追溯执行

统一 SegmentSpec 与 ArtifactManifest，保存每段模型、提示词版本、外部任务 ID、尝试、费用、质检与产物。对象存储采用 outputs/<run_id>/segments/001.mp4 等逻辑前缀，同时保存 manifest.json、analysis.json、adapted_plan.json 与 final.mp4；不要求 Worker 永久保存本地文件。沿用现有媒体 URL 对外契约。

### 第四期：多供应商与成本质量路由

先逐家验证能力及协议，再加入预算、延迟、成功率和历史质量排序。无实际数据时使用透明规则，不宣传自动最优。回退不得丢失参考视频、替换意图或改变授权范围；额外重跑须受预算限制。

## 5. 第一期接口与数据

外部可选字段：

- deconstruct_id：本人同原片成功拆解任务 ID。
- shot_overrides：[{index, description?, narration?}]，index 为来源镜头序号；描述和旁白有长度及数量限制。没有来源时不接受覆盖。

内部 shot_plan：

- version：固定为 1。
- source_task_id：来源任务。
- shots：[{index, start, end, duration, description, narration}]，秒为时间单位，按原片排序，索引连续。

拒绝空镜头、非有限时间、倒序、重叠、非法序号和超限内容。快照只由服务端构造，不直接信任客户端整表。来源无效时扣费前返回中文业务错误；不静默采用错误原片。

## 6. 调用链与主要文件

- mobile/src/pages/studio/index.vue：已拆解时自动携带来源及已有编辑，不增加按钮或必填项。
- backend/app/schemas/generate_task.py：可选字段校验。
- backend/app/services/replica_analysis.py：可信镜头读取、归一化及快照。
- backend/app/services/generate_task.py：扣费前验证、参数固化、原有建单与下发。
- worker/app/services/prompt_builder.py：透传快照，不与九宫格字段混用。
- worker/app/tools/video_tool.py：短片结构约束、多段计划复用及恢复。

## 7. 验收与风险控制

- 不传新增字段时保持原流程，不要求额外拆解。
- 越权、错原片、失败或删除来源、空镜头、非法时间、非法覆盖均拒绝。
- 已编辑描述和旁白进入快照；后续修改不改变已建单参数。
- 短片不因为分镜计划被强制切段；无替换意图的长片完整计划不重复检测或逆推；替换任务复用时间轴，描述按现有安全路径编译。
- 检查点优先，重试不重新选择时间轴或漂移提示词。
- 有替换素材时原片描述不能恢复被替换产品或人物。
- 分开执行 backend 与 worker 测试，避免两个 app 包互相污染；移动端执行仓库实际提供的 H5 构建。
- 不运行生产迁移、部署或付费模型调用；外部服务端到端验证需另行确认环境。
